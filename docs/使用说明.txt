netcheck  ·  Windows 网络工具箱
=================================
作者：依依（为 dad 定制）
版本：v9.6   （构建日期 2026-10-13）
文件名：netcheck_v9.6.exe

★ 版本说明：从 v9.2 起，每次新版本都单独命名（netcheck_v9.x.exe），
  不覆盖旧版本；旧版会原样留在 D:\mod 下，可随时回退。

★ v9.6 更新（重要 bug 修复：在别的电脑上「查完 DNS 程序自己退出」）★★
  现象：在某台 Win11 上做完 DNS 查询后，程序一句话不说就自己关掉了；本机不出现。
  原因：程序内部是「子线程干完活发信号通知界面」的结构。DNS 这个子线程的顺序写错了——
        它先发「完成」通知，**然后才去跑 nslookup**（这一步在别的电脑上可能要好几百毫秒
        甚至几秒，因为那台机器的 DNS 服务器响应慢）。
        界面收到「完成」就以为线程已经结束了，于是把对它的最后一个引用丢掉；
        而 Qt 有个硬规矩：**不能销毁还在运行的线程**，一旦发生就直接 abort 掉整个进程。
        所以表现就是"悄悄退出"，连报错都没有。本机因为 nslookup 快，抢不到这个时间差，
        才一直没复现。
  修复：① DNS 线程改成「先跑 nslookup，最后才发完成信号」；
        ② 全程序所有子线程的释放方式统一改成「托住引用，等它真正结束再放」，
           顺手把「连点两次"查询"」「点停止」这些会撞上同一问题的路径一起修了
           （探测 / 路由追踪 / 端口扫描 / 连接 / DNS / 宽带测速 各页都改了）。
  另外：新增全局异常兜底——万一以后还有没料到的异常，会弹窗提示并把日志写到
        `%LOCALAPPDATA%\netcheck\error.log`，不会再无声无息地退出。

（v9.5/v9.4 的功能一并保留：探测页默认本机网段、国内上传有数值、档位卡片不浮动）

八个功能页（顶部标签切换）：
  ① 探测（Ping / TCPing）
  ② IP 配置（ipconfig）
  ③ 路由追踪（tracert）
  ④ ARP 缓存（arp）
  ⑤ 网络连接（netstat）
  ⑥ 端口扫描
  ⑦ DNS 查询
  ⑧ 宽带测速（国内 / 国外 + 档位评价 + 本机外网信息）

---------------------------------------------------------------
① 探测（Ping / TCPing）        —— 主机/域名网段的连通性、延迟、丢包
② IP 配置（ipconfig）           —— 查看/释放/续约 IP、刷新DNS
③ 路由追踪（tracert）          —— 到目标的每一跳
④ ARP 缓存（arp）              —— IP ↔ MAC 对应表，可删/清
⑤ 网络连接（netstat）          —— 连接/监听，含 PID+进程名，多重筛选
⑥ 端口扫描                     —— 一台主机的常见端口开放情况
⑦ DNS 查询                     —— A/AAAA/MX/NS/TXT/SOA/SRV/CAA/ALL
⑧ 宽带测速                     —— 延迟+抖动+下载+上传 + 档位评价 + 外网信息

---------------------------------------------------------------
⑧ 宽带测速（核心页）
---------------------------------------------------------------
· 测四项核心指标：下载 / 上传 / 延迟 / 抖动
· 参数全点选（默认值已调快）：
    延迟包数（3/5/10/20，默认 3）  下载测试时长（5/6/8/12 秒，默认 6）  上传数据量（4/8/16/32MB，默认 8）
· 节点按「国内 / 国外」分组（v9.4 已按实测重新选址）：
    [国内延迟]  百度 / QQ / 淘宝 / 阿里DNS（**并行测试**，几秒出全部）
    [国内下载]  清华镜像 / 北大镜像 / 哈工大镜像
    [国内上传]  华为云镜像（国内少有的、会真正接收上传的公开测速点）
    [国外延迟]  Cloudflare(one.one.one.one) / Google(dns.google)（并行）
    [国外下载]  Cloudflare（50MB 档）/ OVH 法国
    [国外上传]  Cloudflare
· 结果区分两栏数字：
    ● 国内节点（蓝）：下行 / 上行 / 延迟 / 抖动
    ● 国外节点（红）：下行 / 上行 / 延迟 / 抖动
· 详细表带「区域」列，蓝色=国内 红色=国外，一目了然；每行尾括号里带该节点耗时
· 进度条是全 13 个测点的全局进度（如 "下载 3/3 北大镜像 · 8/13"），
  旁边有「已用 X.Xs」实时计时，测速全程都在动，不会看着像卡死
· ★★ 下载测速「多连接 + 稳态法」（v9.3，解决精度问题）★★
    为什么以前 150M 宽带测出来忽高忽低？三个根因：
      (1) 单条 TCP 连接常被 CDN 限速，或受「带宽时延积」限制，单流跑不满 150M；
      (2) TCP 慢启动：连接刚建立的头 1~2 秒速率从 0 爬升，把这段算进去会严重偏低；
      (3) 运营商「突发加速」：前几秒给你冲到 200M+，之后回落到真实值，取峰值会偏高。
    现在怎么测：
      · 同时开 4 条连接下载，把整条带宽压满（不再被单流限制）
      · 跳过开头 2 秒慢启动，只统计后面的稳态窗口（~6 秒）
      · 节点间取「中位数」做主结果，避免个别节点抽风拉偏整体
      · 结果里会标注「N连接稳态 / 共取 XXX MB / X.Xs」，看得见测量过程
· ★★ 上传测速「稳态法」（v9.4）★★
    上传只有一条连接，所以更要小心「慢启动」：直接拿「总字节 ÷ 总耗时」会严重偏低
    （连接握手 + 前几 MB 的爬升都被算进去了）。现在做法：
      · 分块发送 body，跳过开头一段（最多 4MB）之后再开始计时
      · 只有服务端返回 2xx 才算数（被拒 / 413 一律判为「暂不可用」）
      · 结果标注「POST N MB 稳态 / X.Xs」
· ★ 稳定性要点（v9.1 修复）：
    - 不可达节点「快速失败」：连接阶段最多等 2.5s，不再傻等满整个测试时长
    - 延迟阶段并行执行：5 个节点同时 ping，整体从 ~20s 压到 ~5s
    - 下载速率只统计「首字节到达后」的纯传输时间，排除 TCP 握手/TTFB 干扰
    - 单节点最多读 400MB 就停，避免千兆线路测一次吃掉好几个 GB
    - 全程异常都会被捕获并显示，不会再出现"点了开始却一直没反应"
· ③ 区给出宽带档位评价，举例：
    "你的网速相当于 500M~千兆宽带，典型用途：
     流畅 4K HDR / 10+ 设备同时上网 / 大文件秒下 / 云游戏 60fps；
     延迟 12 ms（优秀 ≤30 ms，主流网游、4K 直播毫无问题）。"
  档位说明：
    · 万兆级专线 (≥3 Gbps)      数据中心互联 / 8K 直播推流 / 大型 NAS
    · 千兆宽带 (≥1000 Mbps)     8K 点播 / 多设备 4K / 云游戏 4K HDR
    · 500M~千兆宽带           流畅 4K HDR / 10+ 设备 / 大文件秒下
    · 300M~500M 宽带          4K / 多设备 / 云游戏 / 高清直播
    · 200M~300M 宽带          1080P 高清 / 5~10 设备 / 一般网游
    · 100M~200M 宽带          1080P 视频 / 3~5 设备
    · 50M~100M 宽带           720P / 2~3 设备 / 浏览购物
    · 20M~50M 宽带            480P / 1~2 设备 / 聊天看新闻
    · 20M 以下                 基础浏览，不推荐视频/游戏
  延迟档位：极佳 (≤10ms) / 优秀 (≤30ms) / 良好 (≤60ms) /
            一般 (≤100ms) / 欠佳 (≤200ms) / 较差 (>200ms)
· 综合评语：用国内档位作为主体，附"国外体验：X 档位；典型用途"
  能直观看出"国内下载很快，但国际出口是瓶颈"这种典型情况
· 全部走 https 公开测速文件，无需安装 tcping.exe / speedtest-cli
· 注意：所有测速都用真实下载/上传字节流测瞬时速率，
  较 speedtest.net 的 10 秒均值略激进，但更能反映峰值带宽

---------------------------------------------------------------
⑧ 宽带测速 · ④「本机外网信息」
---------------------------------------------------------------
点「开始测速」后会先查一次本机外网信息，显示在 ④ 区（五栏）：
    · 外网 IPv4 —— 公网 IPv4 地址（如 61.183.140.6）★v9.3 新增独立显示
    · 外网 IPv6 —— 公网 IPv6 地址（如 240e:...），没有则显示「无」
    · 所在地     —— 中文地名，括号内附英文原值（如 "中華人民共和國 湖北省 武汉 (Hubei Wuhan)"）
    · 运营商     —— 中文运营商，括号内附英文原值（如 "Chinanet"）
    · ASN       —— 如 AS4134，可用于判断骨干归属
数据来源（按顺序自动降级，任一成功即用）：
    IPv4：ip-api.com（ipv4-only，中文）→ api-ipv4.ip.sb → ipv4.icanhazip.com
    IPv6：api-ipv6.ip.sb → ipv6.icanhazip.com
    地理：api.ip.sb/geoip（用户指定的源）＋ ip-api.com 中文增强 → myip.ipip.net 兜底
· IPv4 / IPv6 走**两条独立线路**分别查询，互不干扰，所以两个地址都能拿到
  （旧版正是"只查到了一个源、恰好回的是 IPv6"，才看不到 IPv4）
· 整个查询有 8 秒总预算，任一源卡住会自动切换，绝不会拖住测速
· 「导出CSV」会把外网信息 + 版本号一并写入文件末尾
